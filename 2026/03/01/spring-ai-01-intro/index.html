Spring AI 入门与起点

Spring AI 是什么

之前我带大家把理论基础过了一遍，知道了 Transformer、Token、Embedding、RAG、Agent 这些概念。但概念归概念，作为 Java 开发者，最终要落地到代码上。这个模块的目标就是：用 Spring AI，把这些能力一个一个用 Java 写出来。

这节先聊清楚 Spring AI 是什么、它解决了什么问题，以及它和 LangChain、LangChain4j 的关系。别急着上代码，这些背景搞清楚了，后面写代码才不会迷糊。

一、没有 Spring AI 之前，Java 怎么调大模型


先回到最原始的状态。大模型厂商提供的是 HTTP API，你要用 Java 调用，最朴素的方式就是：

能跑，但有几个问题：

  1. 每次都要手拼 JSON，model、messages 格式每个厂商不完全一样，切个模型就要改代码

  2. 返回值是 JSON 字符串，每次都要自己解析，容易写错

  3. 流式输出、重试、超时、错误处理 全要自己搞

  4. 换个厂商，比如从 OpenAI 换成 DeepSeek，接口格式有细微差别，改起来很麻烦

这就是 Spring AI 要解决的事。

二、Spring AI 是什么


Spring AI 是 Spring 官方出的 AI 应用开发框架，2024 年正式发布 1.0。

我给大家一个最直观的类比：Spring AI 之于 AI 开发，就像 Spring Boot 之于 Web 开发。

Spring Boot 出来之前，写一个 Web 接口要配 web.xml、DispatcherServlet、各种 Bean，很繁琐。Spring Boot 出来之后，加个注解、配几行 yaml，HTTP 接口就好了。

Spring AI 做的是同一件事——把和大模型打交道这件事标准化、抽象化：

  • 不管你用 OpenAI、DeepSeek 还是通义千问，调用方式完全一样

  • Prompt、流式输出、对话记忆、Function Calling，全都封装好了，开箱即用

  • 和 Spring 生态无缝集成，依赖注入、配置管理、测试，用起来就像用 Spring 里的其他组件

三、Spring AI 的核心抽象


Spring AI 的设计哲学是”面向接口编程”。它定义了一套接口，不同的模型提供商实现这些接口。你的业务代码只依赖接口，不依赖具体实现。\

四、Spring AI 和 LangChain、LangChain4j 的区别

大家学 AI 开发，经常会听到这几个名字，容易混：

LangChain

Python 生态里最流行的 AI 应用框架，2022 年出来，生态非常成熟。网上大量教程、示例是基于 LangChain 的。但它是 Python 的，Java 开发者用不了。

LangChain4j

LangChain 的 Java 移植版，社区维护，功能也相当完整。如果你想在 Java 里用类似 LangChain 的风格开发，LangChain4j 是不错的选择。

Spring AI

Spring 官方出品，和 Spring 生态深度集成。不是 LangChain 的翻译，是 Spring 团队自己设计的一套 API，风格更贴近 Spring 开发者的习惯。
